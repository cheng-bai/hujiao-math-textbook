## 五分钟接手

1. 以 Git 仓库根目录为工作目录，检查 `git status --short`、`git remote -v`、`git log -3 --oneline`。不要假定聊天的当前目录就是发布副本，也不要覆盖未提交的其他工作。
2. 阅读本节、[不可破坏的约定](#不可破坏的约定)、[任务路由表](#任务路由表)；按当前任务再读其余章节，不必把全书装入上下文。
3. 只看网站：运行 `python serve.py --port 8000 --no-browser`，打开 `http://127.0.0.1:8000/`。无需安装开发依赖或调用外部 AI。
4. 改一节内容：编辑 `batch/sections/{book_id}/{section_id}.json`，不要直接把生成的 HTML 当编辑主档案。
5. 用单节渲染、相关测试和必要的浏览器/打印检查验证，再扩大范围。没有发布授权，不自动提交、推送或部署。

## 1. 产品定义

### 我们在做什么

把五册沪教高中数学教材、正式教参与有教学价值的交互资源，组织为一套可连续阅读、可备课、可分发学生材料、可按内容打印的网页教师工作书。

最终目标不是“扫描件上网”，也不是“在教材里堆动画”，而是：

- 教师快速找到概念、题目、解法与相关教学说明。
- 教材主线清楚，教参在需要的位置解释引入动机、关键转化、条件和易错点。
- 重要公式、思想方法与适用条件醒目，但不破坏正常阅读。
- 对真正难理解的变化、结构和临界状态，用可操作图像降低理解负担。
- 教师版与学生版共享可靠内容来源，但学生交付物物理排除答案与教师材料。
- 他人取得仓库即可使用，并能在不依赖原作者电脑、Codex、付费 API 的前提下维护。

### 面向谁

**主要用户是高中数学教师。** 典型场景是课前备课、查找例习题、研究解法、课堂投屏、生成纸质材料。

学生阅读和练习是明确保留的第二场景，不是把教师页隐藏答案就冒充学生产品。学生独立页面和 ZIP 有不同的内容边界。

### 目前不是什么

- 不是已完成全书数学与出版审定的正式出版物。
- 不是成熟的账号、权限、付费或私密试卷系统。
- 不是完整教师工作台或试题篮；相关项目暂不接通。
- 不是新的前端框架展示工程；不要为普通阅读功能重写成大型应用。

## 4. 核心使用流程

### 阅读与备课

总目录 → 册目录 → 章节教师版 → 本页索引定位 → 展开/隐藏答案与教参批注 → 按需要进入交互模块。

本页索引搜索目前基于标题、重点标记及题干的短摘要。摘要生成会去除公式；它不是数学公式搜索，也不是题目全文搜索。不要仅通过改标签文案就把它宣称为全书检索。

### 学生分发

从教师页面进入独立学生版，或者下载对应 `student.zip`，完整解压后打开。ZIP 应包含所需脚本、样式、KaTeX 和公开图片，不依赖相邻教师目录。

学生材料不应包含答案、解析、教师说明、教师专用图片、来源副本或教师版实验载荷。题干/题图本身是否藏有答案痕迹仍需人工检查。

### 可视化编排

资源栏预览 → 拖入或选择合法锚点插入 → 调整状态及学生可见性 → 必要时撤销 → 导出编排 JSON。

编排与交互状态主要保存在当前浏览器的 `localStorage`，按册隔离；没有云同步。换设备或清理浏览器前先导出。不同来源、端口和 `file://` 下的浏览器存储可能不互通。

### 打印

打开“按内容打印” → 选择正文、仅试题、试题加答案或完整内容 → 按模块、题型、范围筛选 → 选择是否附带教参说明和来源行号 → 预览 → 系统打印。

屏幕上的展开状态不应决定打印内容。打印使用独立克隆与筛选，不通过破坏原页面结构生成。

## 不可破坏的约定

1. **教材与教参来源只读保留。** 编辑优先落在结构化底稿。OCR 修复、原解保留、编辑补解和新教学说明必须能区分。
2. **数学内容不能为排版或测试让步。** 不删题维持通过率，不换条件消除冲突，不按列表顺序猜配答案，不把图像或有限采样写成证明。
3. **学生交付物物理排除教师内容。** CSS 隐藏、关闭 `<details>`、共享口令都不是内容隔离。
4. **题目与锚点身份稳定。** 不因重排、润色或重建重新生成已有题目 ID；不要用当前页内顺序代替身份。
5. **保留来源和恢复依据。** 行号指原 Markdown 来源范围，不冒充印刷页码。不能伪造教参来源为编辑新增解答背书。
6. **封存资源不可原地覆盖。** 更改已发布资源应升级版本并重新校验，不直接改 manifest 哈希让错误“通过”。
7. **静态阅读可独立使用。** 不无故引入网络公式服务、外部图片依赖、付费 API、Codex 或本机数据库作为阅读前提。
8. **不擅自接通其他项目。** 本项目与教师工作台/题篮的约定只是一份设计方案；跨项目代码、消息和发布需要对应授权。
9. **不覆盖并发或既有工作。** 先检查 dirty 状态，分清任务相关改动与本地试点，不使用全盘重置或无差别暂存。
10. **完成声明必须分层。** 文件存在、静态检查、公式渲染、视觉抽查、数学复核、教学审定和线上部署互不替代。

## 5. 内容与视觉设计原则

### 内容层级

已有实现仍含较长的篇首教参块。后续建议演进为“简短备课提要 → 教材主线 → 就地教学说明 → 可展开完整来源”，不是静默删掉完整原文。

概念、公式、思想方法、条件提醒应有明确语义标签，而不只涂颜色。例题的解法与教师说明要围绕实际转折，不机械套一套重复栏目。

新写或润色的数学解析优先高中方法：保留完整题目，说明关键构造动机、方法选择、分类边界与必要证明；常规运算可合并。仅保留原解或纯转录时不要擅改文风与推导。

### 现有视觉语言

保留纸张感浅色背景、深绿正文结构、少量砖红强调、中文宋体阅读气质与紧凑布局。字体依赖浏览器可用的中文字体回退，不承诺所有系统字形完全一致。

不要未经同意换成通用卡片后台、紫白 AI 风格或全新框架。优先降低重复信息与操作密度，而不是单纯缩小字号。移动端注意工具栏占屏、长公式横向处理、目录抽屉焦点和打印面板。

### 可视化的准入标准

必须指出对应原文位置、读者理解障碍、关键视觉构造和预期收益。重点是变化关系、空间结构、临界状态、反例与条件必要性，而不是让简单定义动起来。

数学模型正确、交互可用、离线可读、视觉质量、教学价值分别评价。截图存在不代表人工读图签核；模块数量不代表教学效果。

用户已否定部分旧探究的深度和展示效果。基线“7 个深度探究”入口仍含有被质疑的线面角与基率主题，尚未完成推荐清理；不能把它们当作已获得认可的标杆。后续宜分“正式推荐 / 实验待审 / 退回重做”，但这一治理界面尚未实现。

## 6. 技术架构

本节描述当前运行结构；目标模块边界、兼容迁移和证据失效策略见 [AI 迭代架构](../ARCHITECTURE.md)。`scripts/ai_context.py` 与 `architecture/task-map.json` 是已落地的只读接手入口，目标 `hujiao/`、`reader/` 等目录仍属计划，不要当成已完成重构。

```text
sources/textbooks/ + sources/paired/ + sources/visuals/
          | 来源快照、图片、历史配对与既有交互输入
          v
batch/manifests/catalog.json
batch/sections/{book_id}/{section_id}.json  <-- 日常内容编辑主档案
          | 校核、编辑修订、稳定 ID、来源范围
          v
scripts/batch_render.py
  图片映射 -> 强调范围调整 -> example_guidance.py 保守归位
  -> build_sample.py 中复用的渲染组件 -> 师生 HTML / 学生 ZIP
          |
          +-- scripts/book.css / book.js：阅读、索引、公式、打印
          +-- scripts/visual-book.* + visual-assets/：交互与编排
          +-- scripts/site-access.*：前端口令入口
          v
outputs/五册教材教参整合/
          |
          +-- batch_validate.py：浏览器、公式、离线、打印检查
          +-- batch_run.py：续跑、状态、目录和入口生成
          +-- check_release.py：静态引用、哈希、ZIP、部署闭包
          v
Git main -> CI -> 手动触发 Pages -> 线上核对
```

### 技术栈与依赖

- 阅读端：原生 HTML、CSS、JavaScript；不要求 Node、Python 或前端构建工具才能阅读。
- 公式：本地 KaTeX，正文使用标准 LaTeX；渲染错误会记录，不能仅显示原始公式文本后称验收通过。
- 构建端：Python 3.10+，`markdown-it-py` 渲染 Markdown，标准库处理路径、JSON、ZIP、哈希及服务器。
- 检查端：BeautifulSoup、PyMuPDF、Playwright；完整版本在 `requirements.txt`。
- 部分交互的模型测试/生成需要 Node.js 20+，不等于读者需要安装 Node。
- 部署：GitHub Actions + GitHub Pages，纯静态站点。无后端数据库、账号服务或云端状态同步。

出现矛盾时，先核对当前源码、数据和实际产物；日期更早的交付报告是历史证据，不自动推翻当前实现。`batch/CONTRACT.md` 保留了早期代理分工，不代表现在可以重新提取覆盖所有编辑。

## 8. 内容数据契约

### 节级对象

`batch/sections/{book_id}/{section_id}.json` 使用 `schema_version: 1`。主要字段：

| 字段 | 含义 |
| --- | --- |
| `id` / `book_id` / `chapter` / `section` | 节身份、册身份和来源编号 |
| `title` / `chapter_title` / `book_title` | 正式显示信息 |
| `sources` | `book`、`teacher` 对应仓库内来源路径 |
| `source_hashes` | 来源文件字节 SHA-256，用于发现漂移 |
| `blocks` | 顺序内容块，是主线、题文与教师说明的载体 |
| `issues` | 缺答、错配、缺图、来源冲突等显式问题 |
| `editorial_repairs` / `independent_review` | 如存在，记录编辑与复核；不是有字段就算通过 |

公开副本的持久路径应为**项目根相对路径**。脚本内部解析后得到绝对路径是正常的，但不能把本机目录再次写回发布数据。`.gitattributes` 的 `* -text` 保护来源字节，不要随意启用换行自动转换。

### 内容块

现有类型为 `section`、`heading`、`prose`、`question`、`teacher`、`editor`、`intro`。共有字段包括 `id`、`title`、`markdown`、`provenance`。

题块至少关注：

```text
id                   稳定身份，如 x1-2-2-ex-1
category             例题、练习或习题等原有分类
markdown             完整题干及题图
provenance_question  题目来源
answer               当前混合存放答案与解答正文
answer_provenance    解答来源
teacher_analysis     教参说明或明确标记的编辑教学说明
analysis_provenance  教参说明来源
```

当前没有统一的 `final_answer` / `solution` 拆分，也没有正式全量 `difficulty`、知识点 ID 或方法标签契约。新增这些字段是 schema 设计和渲染迁移任务，不是给 HTML 添几个星星。

### 来源、补解和数学修订

`provenance` 中 `source: book/teacher` 与 `start/end` 对应原 Markdown 的行号范围。不要把输出 HTML 行号、截图页数或推测印刷页码混进去。

如果获准自行补解：保留完整题意，独立推导，明确“编辑补解”，记录题目依据、方法和独立复核。当前底稿存在 `answer_editorial` / `editorial_answer` 等历史修订形式，验证器有相应判断；先读现有相邻例子和 `has_answer_basis()`，不要捏造来源字段让检查通过。

题目、答案或图形有冲突，先记录问题与数学裁定。源文件默认不改，修订落在底稿与证据中。

### 重点标记

`emphases` 使用 `{start, end, kind, title, id}` 标记现有 Markdown 切片，类别主要为 `concept`、`formula`、`method`、`condition`。旧 `definition` 在渲染时归一为 `concept`。

修改带重点标记的正文时重新校核范围：不能截断 LaTeX、指向错误段落，不能复制同一个公式作为“新增强调”。图片路径映射会改变字符串长度，渲染器已有范围调整，不要在生成 HTML 中再猜偏移。

## 9. 教参例题说明归位机制

执行位置：章节图片 URL 映射完成后、HTML 渲染前，调用 `prepare_example_guidance(blocks)`，返回新的块与报告，输入底稿不被就地改写。

仅对明确的正式教参分析块进行保守归位：段落明确指向例号、所属小节一致、被引用的所有例题能唯一找到，才移入对应 `teacher_analysis`。共有说明可对应多个题块，不能把关联数当唯一例题数。

无法确认的段落留在原处。已有相同说明不重复附加；连续构建应幂等。具体边界、续写判断与审计字段见 [例题教参归位规则](例题教参归位规则.md)。

基线仍有 4 组未归位：

| 节 ID | 未确认原因 |
| --- | --- |
| `x1-4-4` | 1 组共有说明引用例 3、4，其中例 4 无法唯一匹配 |
| `bx3-13-5` | 1 组说明引用的例 6 未找到 |
| `x2-8-2` | 2 组说明实际属于 8.3 的例 1 与例 2、3，不能贴给 8.2 |

解析归位后位于答案区域内部：隐藏答案时一并隐藏；教师批注仍可单独隐藏，打印也有独立选项。学生物理输出不应含这些说明。

## 10. 构建产物、指纹与状态

每节输出通常包括：

- `teacher.html`、`student.html`：师生页面。
- `student.zip`：独立离线学生包。
- `content.json`：渲染派生块，已经过图映射、归位等处理；不是源底稿。
- `teacher-guidance.json`：此次归位的来源关系与未确认项。
- `build.json`、`metadata.json`：构建信息、来源哈希、问题与产物哈希。
- `validation.json`：实际检查结果。`verification/` 中的截图、PDF 等通常被 Git 忽略。

每册 `_shared/` 共享阅读脚本、样式、KaTeX 和实验载荷；来源快照位于对应册的 `_sources/`。输出中的 `book-<hash>` / `private-<hash>` 图名用于运行去重，不等于可读的原教材图号。

构建指纹涵盖底稿、渲染脚本/组件、共享运行资源、相关来源及图片等。共享脚本变动可能使很多章节的旧构建/检查失效，这是正确行为，不要复制旧“通过”状态刷绿。

目录页显示“通过”同时要求：`validation.json` 状态为 `passed`，其 `build_fingerprint` 与当前构建一致，以及 `batch/state/sections/{id}.json` 状态为 `validated`。单独运行验证器只更新验证记录，不更新批次状态；需要定向采用已有检查或运行定向批次来完成状态闭环。刷新后“已核验数”下降不等于正文丢失，也可能是旧证据失效或状态尚未同步。

`--force` 用于明确需要的重新构建或复验，不作为无条件全书恢复按钮。反复重建同一题会更新生成产物，不能把这些变化混同于原题被重新编辑。

## 11. 可视化实现与维护

### 资源来源与生成器

- `scripts/textbook-labs/` 按族组织实验，`scripts/build_textbook_labs.py` 生成载荷、册级目录和选择审计。
- `scripts/build_conic_labs.py` 适配 `sources/visuals/` 中既有椭圆/圆锥曲线资源，生成师生载荷和来源记录。
- `scripts/build_visual_gallery.py`、`build_deep_lab_index.py` 生成总览入口，不能只手工改总览 HTML。
- `scripts/package_textbook_labs.py` 封存资源，要求真实结果证据；没有视觉复核凭据时保持 `pending`，不得由截图文件存在推断视觉通过。

生成器会改多个文件。新增实验前先读目标族文件与脚本的 `--help` / 入口，明确影响范围；不把所有实验源码一次读入上下文。

### 运行和编排协议

模块运行在 `sandbox="allow-scripts"` 的 iframe 中，通过受限消息与宿主同步状态。不要为修复方便加入 `allow-same-origin`、放开沙箱或直接访问另一项目的存储/API。

编排记录含模块身份、版本、资源哈希、场景、章节、锚点、实例身份、学生可见性和参数状态。导入会检查册次、版本、允许章节/锚点与参数范围；新功能不能绕过这些校验。

屏幕折叠的原文应可恢复。移除/隐藏实验时恢复对应正文，打印正文与完整内容时恢复完整原文。静态代表图不是“当前滑块状态的精确截图”，除非另行实现并验证。

### 封存和升级

资源目录形如 `outputs/教材可视化资源库/{slug}/{version}/`，有的版本已是 `1.0.1` 等，不能写死 `1.0.0`。检查其 manifest 和文件哈希，不原地覆盖发布版本。`library.sqlite` 是可选本地索引，不是阅读网站运行前提，也不随 Git 发布。

## 12. 难度与高清图片的后续契约

### 难度标注

这是下一阶段产品任务，不能把以下建议写成现有 schema：

- 先明确对象是例题、整题还是小问，保存量规版本、适用学段与评估依据。
- 复用 30 题样本时先解决未冻结项和星级边界；样本自己的量规不等于 HCT，不静默更名。
- 保存建议星级、主要卡点、判定依据、独立复核分歧和确认状态。
- 星级与题型、方法分开。篇幅、计算量、教参答案长短不能单独决定难度。
- 先校准一节，再按章节小批量扩展；不要为追求覆盖率自动填满所有字段。

### 图片重绘

优先几何图、函数图、统计图等可以准确建模的内容；实物照片不强制转为代码图。重绘时同时核对条件、标号、实虚线、透视关系、定义域和比例含义。

建议来源身份采用“册 ID－节 ID－原图号－用途”，例如本地小样中的 `x1-2-2_图2-2-1_椭圆拉绳.svg`。同时保存原路径/哈希、新 SVG/生成代码、复核记录和替换映射。图号缺失或重复时显式增加稳定消歧身份，不能靠不断改名解决。

原图保留作核对，不直接删除；批准替换后再修改对应底稿或资产映射，重建并检查网页、黑白打印和学生包。必须有真正的矢量内容，不能把低分辨率图片包进 SVG 就声称高清重绘。

## 13. 打印、学生隔离和入口安全

### 打印底线

当前默认围绕 A4、100% 缩放检查。容得下一页的题块尽量不拆；超过单页的长题或长解析允许自然续页，不能靠极小字号、删推导或裁切图像“解决”。

题干、题图、答案、教师说明的组合变化会影响高度。共享 CSS 变动后，应复验长题、长公式、带图题、教师说明和学生版，不仅看首页是否漂亮。

打印信息密度还可优化，但“每页塞得更多”不是唯一指标：整题可读、公式不裁切、来源可选、学生不泄题同样重要。

### 共享口令不是账号认证

当前口令为 `xdf3.1415926`，源配置在 `scripts/site-access.js`，通过标记使用 `sessionStorage`；输入口令本身不保存，页面提供重新锁定。

这是公开源码中的前端门禁，可被绕过；原文件、ZIP 和封存资源仍公开。封存 HTML 未统一加入门禁，以免破坏哈希。关闭存储或 `file://` 限制可能导致每页重复输入。

正式认证留待后续设计，必须保护内容请求本身，不是只在 HTML 上再叠一层表单。不要在当前公开仓库提交 token、账号密码、学生私密信息或保密试卷。

改口令或入口样式后：重建受影响章节及学生 ZIP，并运行 `site_access.py` 同步第一方入口。只改 `outputs/_shared/` 不能更新每册共享文件和已打包 ZIP。

## 14. 可直接使用的操作步骤

以下命令从仓库根运行。`python` 应指向 Python 3.10+；macOS/Linux 也可用 `python3`。含环境变量、Shell 变量的片段是 POSIX Shell 写法，PowerShell 需使用对应语法。

### A. 只阅读，无开发安装

```sh
python serve.py --port 8000 --no-browser
```

浏览器进入 `http://127.0.0.1:8000/`。默认仅本机服务，端口不通先查进程，不重复启动很多服务器；占用时换端口。对他人演示线上版本不依赖本地服务器。

### B. 第一次做开发

先复用已有合适环境；没有时只建一套：

```sh
python -m venv .venv
# macOS / Linux
source .venv/bin/activate
# Windows PowerShell 使用 .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m playwright install chromium
```

浏览器启动逻辑优先 Playwright Chromium，必要时回退本机 Chrome。已有 Chrome 可设置 `HUJIAO_BROWSER_CHANNEL=chrome`。不要反复安装多份浏览器。

### C. 单节修改闭环

```sh
# 编辑前检查，再按任务修改底稿或模板
git status --short

python scripts/batch_render.py --section batch/sections/x1/x1-2-2.json --force
python scripts/batch_validate.py --section batch/sections/x1/x1-2-2.json --force
python scripts/batch_run.py --adopt-existing --section x1-2-2
python scripts/check_release.py
git diff --check
```

`batch_validate.py` 会启动浏览器并产生验证 JSON、截图和打印 PDF，不是纯静态命令。定向 `--adopt-existing` 核对当前指纹、产物哈希和验证结果，写入对应批次状态并刷新目录，不重复打印；仅 `--portal-only` 不会完成这一步。修复后只重跑受影响检查，不把全量 PDF 生成当每轮默认动作。

### D. 再生整册或全书

```sh
# 只重建选修一；仍先完成单节样板
python scripts/batch_render.py --catalog batch/manifests/catalog.json --book x1 --force

# 共享源码调整确需更新五册时
python scripts/batch_render.py --catalog batch/manifests/catalog.json --force
python scripts/site_access.py
python scripts/batch_run.py --portal-only
```

重新渲染不等于重新提取。`batch_extract.py` 会重建底稿，可能覆盖已编辑答案与修订；除非明确修改输入或解析规则并获准迁移，不运行。

### E. 已授权的批次续跑

```sh
python scripts/batch_run.py --section x1-1-1
python scripts/batch_run.py --book x1 --limit 2
python scripts/batch_run.py --adopt-existing
```

默认批次包含构建与浏览器检查，可能耗时并产生 PDF。不要把它当仅刷新目录的命令；仅刷新用 `--portal-only`，它也会补齐第一方入口门禁。

## 15. 测试矩阵与验收口径

### 快速代码与全量结构检查

```sh
python -m compileall -q scripts serve.py tools/anatomy/scripts
python -m unittest discover -s scripts -p test_example_guidance.py -q
python -m unittest discover -s scripts -p test_portability.py -q
python -m unittest discover -s scripts -p test_reading_features.py -q
python scripts/test_build_roundtrip.py

```

前三个 unittest 模块在基线合计 20 项，后续新增测试后数量会变化。`test_reading_features.py` 需要 BeautifulSoup，不能把“CI 目前未安装此依赖”误当该测试不需要依赖。

| 检查 | 能证明 | 不能证明 |
| --- | --- | --- |
| `test_example_guidance.py` | 匹配、保留、幂等与来源规则 | 全书每条教参的语义均已人工认可 |
| `test_reading_features.py` | 全部章节索引可达、归位嵌套、学生排除、ZIP 与共享资源 | 手机上的实际操作体验、公式内容正确 |
| `test_portability.py` | 路径、编码及浏览器回退等回归 | 所有操作系统桌面均人工运行过 |
| `test_build_roundtrip.py` | 隔离临时输出的重建与缓存一致 | 完整线上部署成功 |
| `check_release.py` | 引用、哈希、ZIP、强调范围与锚点等静态完整性 | 公式已真实渲染、证明正确、图形有教学价值 |
| 单节 `batch_validate.py` | 当前构建的浏览器、离线、公式与打印检查 | 当前章节每一道答案已数学复审 |
| 独立数学复核 | 被明确覆盖的题目/模型/条件 | 未覆盖章节或修改后的新版本 |
| 人工视觉/教学审阅 | 实际看过的图、页面及场景的判断 | 所有参数、所有设备、所有模块自动通过 |

### 代表性浏览器回归

共享阅读功能变化后，基线选取的五册样本是 `bx1-2-3`、`bx2-8-2`、`bx3-10-3`、`x1-2-2`、`x2-5-3`。使用各自 `batch/sections/{book}/{id}.json` 路径验证，不只测一册。

现有 `test_visual_book.py`、`test_visual_layout_state.py`、`test_conic_labs.py`、`test_deep_lab_experience.py` 等用途不同，按变更范围选择。

`test_textbook_labs.py` 是较早的全量专项入口；本基线未调用新加入的 `unlock_access()`，不能把旧通过记录当作门禁加入后的当前全量回归。使用前核对并适配入口，再运行对应族/范围；不要先启动整套昂贵测试再发现页面被门禁遮住。

验证截图与 PDF 的路径通常属于 Git 忽略产物。其他机器没有截图不代表网页依赖缺失；反过来，旧截图存在也不代表当前版本已经验收。

## 16. Git、CI 与 Pages 发布

仓库：[cheng-bai/hujiao-math-textbook](https://github.com/cheng-bai/hujiao-math-textbook)。
线上：[GitHub Pages 阅读入口](https://cheng-bai.github.io/hujiao-math-textbook/)。

### 当前流程

- `main` 是基线发布分支。接手时仍要先检查远端和差异，不强推，不覆盖别人的提交。
- `ci.yml` 在 push、pull request 和手动触发时运行，矩阵为 Windows/Linux、Python 3.10/3.12。
- 当前 CI 检查编译、静态发布、可移植性及重建回读；**还没有纳入全部新增索引/归位测试与真实浏览器打印回归**。
- `pages.yml` 仅 `workflow_dispatch`，推送成功不会自动部署网站。
- Pages 发布内容为根 `index.html`、完整 `outputs/`、`batch/reviews/`。缺少后者会破坏页面来源/复核链接。
- 部署前对实际 `_site` 做闭包检查；不是把仓库所有开发文件都暴露为网站根。

### 获得发布授权后的步骤

```sh
git status --short
git fetch origin
git log -3 --oneline
# 先查看实际 diff；只暂存本任务确认的文件，不使用无差别 git add .
git add <本任务确认的文件或目录>
git diff --cached --check
git diff --cached --stat
git commit -m "Describe the verified change"
git push origin <确认的发布分支>

# 获取完整 SHA，用于准确筛选工作流
git rev-parse HEAD
gh run list --workflow ci.yml --commit <完整提交SHA> --limit 1
gh run watch <CI运行ID> --exit-status

# CI 通过后才发布；本基线发布分支为 main
gh workflow run pages.yml --ref main
gh run list --workflow pages.yml --commit <完整提交SHA> --limit 1
gh run watch <Pages运行ID> --exit-status
```

命令中的尖括号是待替换参数，不可原样执行。短 SHA 过滤可能查不到运行；任务刚提交时列表也可能暂时为空，不因此认定未触发。不要为了查状态重复发起发布。

### 发布成功的完成标准

1. 远端提交与预期发布 SHA 一致，CI 通过。
2. Pages 工作流成功且部署指向该版本。
3. 线上入口、一个受影响教师页、相关共享资源可访问；必要时使用缓存参数区分旧 CDN 内容。
4. 关键线上文件与本地已验证版本内容/哈希相符；涉及交互改动时再做在线操作抽查。
5. 报告代码推送、CI、部署、线上核对四个状态，不能只说“已推送”就声称网站更新。

基线 `33928a3` 已完成 CI、Pages 和 8 个关键线上文件的一致性核对；这是该提交的记录，不是对未来改动的保证。流程升级警告与失败分开处理，非阻断警告不等于本次部署失败。

## 17. 高效批量与多 AI 协作

- 先把一个真实章节做成可验收样板，冻结字段、模板、检查规则，再按小批次推广。
- 每个 worker 只读本手册相关节、自己的任务合同、目标章节和必要来源范围，不复制全聊天、全书或全部实验源码。
- 制作与复核分开；数学重算、教学价值和前端实现不是同一种检查。
- 内容编辑、共享渲染器和独立复核应有明确文件所有权。不要多个 worker 同写共享 CSS/JS，或同时重建同一章节。
- 浏览器与打印低并发；使用当前指纹和状态续跑，失败节点隔离，不阻塞无关章节。
- 共享源码更新后重启已有 worker。旧进程不能因为读到新文件哈希就冒充执行过新逻辑。
- 每批落盘“已处理 ID、底稿/构建指纹、结果位置、未解决项、下一步”，而不是只发一条聊天“完成”。
- 不重复全量备份、复制整个字体库或反复安装环境。统计空间用十进制 MB，清理时只处理本任务可再生且无依赖的中间物，遵循授权并保持可恢复。

## 18. 常见故障定位

| 现象 | 优先检查 | 不要这样修 |
| --- | --- | --- |
| 改底稿后网页没变 | 是否渲染了正确副本/章节；浏览器缓存 | 直接改另一个目录的 HTML |
| 发布后线上仍是旧内容 | Pages 是否手动触发、SHA、CDN、资源内容 | 反复 push 同样内容或强推 |
| `source-drift` | 原来源字节、换行、路径、确切修改原因 | 改 expected 哈希掩盖来源漂移 |
| `missing-answer` 或数学冲突 | 完整题意、来源、编辑补解授权和复核 | 删题、猜答案、用题干填答案 |
| `missing-image` | 底稿图路径与原文件是否存在 | 下载不相关图替代，或清掉图引用 |
| 公式显示原始 LaTeX | `window.__mathErrors`、公式边界、KaTeX 资源 | 用纯文本截图冒充公式渲染 |
| 学生包依赖教师目录 | ZIP 白名单、共享文件和公开图引用 | 直接打包整个章节目录 |
| 索引跳到遮挡位置 | 工具栏 offset、解锁事件、折叠 details、hash | 写死所有设备的固定偏移量 |
| 实验没出现或旧编排异常 | 资源目录、章节锚点、版本/哈希、当前 localStorage 配置 | 不说明就清空用户浏览器状态 |
| 编排导入拒绝 | 册次、schema、资源版本、锚点、参数范围 | 移除校验或绕过沙箱 |
| 长题续页 | 是否真的超出一页、题图与解析组合 | 强缩字号、裁图、删推导 |
| 检查通过数量下降 | 当前构建与 `validation` 指纹、结果及 `batch/state/sections/` 状态是否一致 | 把旧 JSON 复制为新通过记录 |
| 口令每页重复要求 | file 存储限制、浏览器策略、来源/端口变化 | 假称已有正式登录服务 |
| 资源封存哈希不一致 | 是否改了已发布版本文件 | 原地重算 manifest 让它通过 |

## 19. 下一阶段产品优先级

这是基于当前状态的建议，不是已经授权执行的任务列表。

**第一阶段：把一节做成标杆。** 建议用椭圆，重组篇首教参、就地说明和完整来源；精简手机主操作，撤出未认可实验的主线推荐，补上新增功能 CI。

**第二阶段：建立可信的题目与图片资产。** 复查本地 30 题和 10 图样本，确认难度量规、题块/小问粒度、原图定位、替换流程和独立复核，再逐章推广。

**第三阶段：提高检索和使用效率。** 五册统一检索、知识/方法关联、简答与完整解析分层等，均应基于统一数据，不维护两套互不关联的可编辑正文。学生检索索引必须排除教师内容。

**暂缓：** 大型框架迁移、继续无差别批量增加动画、复杂账号体系、未协调的题篮接入。正式认证是否升级与内容保护范围必须单独决定。

本地校准、图样、4 组未归位说明、未完成的数学审定应保持显式状态，不能在新版文案中隐去。

## 20. 每轮交付的最低说明

交接给用户或下一位 AI 时，至少说明：

- 做了什么，明确章节、题目 ID、模块或文件范围。
- 哪些是源底稿修改，哪些只是再生输出；有没有改原来源。
- 实际运行了什么检查，结果在哪，哪些属于旧证据。
- 数学、视觉、教学与部署分别确认到哪一步，未完成什么。
- 有无未提交/未发布试点，有无外部工作台改动或新依赖。
- 如果发布，给出提交、CI、Pages 与线上核对状态；如果未发布，直说本地交付。
- 若涉及清理，给出本任务可归因的新增、删除和净增范围，不以目录总大小充当本轮增量。

不要用“全部完成、全面通过、完整审定”替代具体范围。用户最终需要的是好用且可信的教师工作书，不是越来越多的生成文件。
