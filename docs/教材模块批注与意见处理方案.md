# 教材模块批注与意见处理方案

状态：第一轮设计，尚未接入网页、存储或发布。目标是让读者针对教材中的具体内容提出意见，并由教师集中处理；不是个人浏览器笔记，也不是公开评论区。

## 读者提交

1. 在章节内的概念、例题、习题、教参或交互模块旁选择「提建议」。保持正文紧凑，按钮不出现在打印结果中。
2. 表单自动显示册次、章节、模块名称和定位信息；读者选择「内容或答案」「表达与教学」「图形或交互」「排版与功能」「其他」，填写意见，可选填写称呼。星级评价为可选项，不替代文字说明。
3. 明示意见会发送给网站管理者，不公开展示；提示不要填写学生姓名、联系方式等敏感信息。提交中防止重复点击；只有服务端确认保存后才显示成功和反馈编号，失败时保留输入并允许重试。
4. 不要求读者登录，也不承诺匿名追踪或处理答复；如未来需要回复或查询进度，应另行设计身份、联系方式及隐私机制。

## 定位与数据

- 每条意见保存：反馈编号、提交时间、册次 ID、章节 ID、模块稳定 ID、模块类型、当时的简短标题或摘录、页面版本标识、类别、可选评分、内容及可选称呼。
- 优先复用正文已有的稳定 ID，例如 `bx1-1-1` 章节 ID 和题块 ID；不使用屏幕坐标或页面元素序号作为长期标识。无稳定 ID 的模块先补充源数据标识，再开放定点反馈，不能靠猜测绑定。
- 摘录只作辅助校对，不作为锚点；章节改版后若 ID 找不到或内容变化，管理端标记「定位待核」，保留原始内容与历史版本信息，不自动迁移到相似模块。
- 提交内容按纯文本处理，限制长度；服务端验证字段、模块和评分范围，避免注入、滥用及将任意路径当作定位链接。

## 教师处理

1. 管理者通过受保护的管理入口查看全部意见，可按状态、册次、章节和类别筛选，显示提交时间与模块定位。
2. 打开意见后，查看完整内容、定位信息与原文上下文，跳回对应章节。处理状态依次可选「待查看」「待核实」「计划处理」「已处理」「暂不采纳」；状态和内部备注不公开。
3. 数学正确性、原始来源与教学建议分开核查；意见不是事实，不能自动修改教材。采纳后按现有底稿编辑、复核和重新构建流程处理。
4. 标记「已处理」时记录处理说明及对应版本或变更依据；建议支持导出备份和筛选结果，明确导出包含意见内容，妥善保管。

## 权限、运行和边界

- 现有 GitHub Pages 是静态站，浏览器共享口令不是身份认证；它不能直接安全保存所有读者的意见，也不能保护管理列表。公开线上使用需要另一个持久化接收服务和真正的管理者认证。
- 读者只允许提交，不能读取意见列表、枚举反馈或修改状态；只有经过认证的管理者可以读取、导出和处理。服务需具备服务端校验、频率限制、持久化备份以及传输加密；服务凭据绝不能写进静态网页或学生 ZIP。
- 在选定和配置服务前，可在本机运行独立试验服务验证流程，但本机 SQLite、浏览器 localStorage 或下载文件均不等于线上多人汇总。离线或学生包无服务时应明确提示不可提交，不显示虚假的成功状态。
- 不上传教材全文或教师专属内容；仅传提交所需的定位信息、短摘录和用户填写内容。保留期限、删除机制、服务提供方与实际隐私告知需在公开使用前确定。

## 分阶段验收

1. **单节样板**：以 `bx1-1-1` 为候选，核对稳定模块 ID，在教师版测试提交、成功回执、网络失败和重复提交；确认不破坏原有阅读、打印及公式。
2. **本地处理闭环**：用独立试验数据验证筛选、定位、状态变更、持久化、导出和服务重启；检查纯文本安全及无效输入。试验数据不混入真实反馈。
3. **服务与权限**：确定真实托管与身份方案后，验证不同读者的意见在管理端汇总、未登录者不能读取管理数据、失败不丢内容及备份恢复。
4. **扩展与发布**：核对其他模块的稳定 ID，并检查学生版物理隔离与离线提示；经用户确认后再部署，线上提交和回执以真实服务验证为准。测试通过仅代表覆盖范围，不等于全书内容已审定。

## 待确定

线上汇总需要选定可持续使用的服务及管理者认证方式；在未确定前，本方案不指定第三方账号、不创建云资源，也不声称已可线上接收意见。是否开放学生版提交、是否接受附件及保留期限，公开上线前另行决定。
