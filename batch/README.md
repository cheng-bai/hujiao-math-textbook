# 五册教材教参整合：恢复与迭代

接手前先读 [产品概览](../PRODUCT.md)，详细操作见 [产品与 AI 接手手册](../docs/产品与AI接手手册.md)。本文侧重批次执行；正常内容修改从既有 `batch/sections/` 开始，重新提取可能覆盖编辑成果，不是启动或刷新网页的前置步骤。

## 工作边界

主交付为本地网页版，不改原教材、教参，不接题篮。范围是必修第一、二、三册与选择性必修第一、二册；先做选修一。延续已认可样章的紧凑阅读、真实公式、答案隐藏与模块化打印，不另起一套排版技术。

## 三层流水线

1. `scripts/batch_extract.py`：章级结构扫描、节级中间底稿、来源行号与图片、题答显式配对、已核OCR修复和原文重点标注。全书内容不进入同一个AI上下文。
2. `scripts/batch_render.py` / `scripts/batch_validate.py`：复用样章渲染组件，教师与物理隔离的学生双版，共享资源按册复用，学生包仅含必要资源。一个浏览器串行验证，避免并发打印挤占内存。
3. `batch/reviews/`：独立复核记录。逐题结构对账与重点数学重算分开记录；不把脚本通过写成数学全部通过。

每节使用稳定ID、源哈希、模板/脚本指纹与产物哈希。无变更的通过项缓存跳过，失败项隔离后继续，不重复读取/重写全书。

## 常用命令

从项目根目录执行：

```bash
# 重新提取指定册，只有输入/解析规则改变时才需要。
python3 scripts/batch_extract.py --books x1

# 默认依次跑 x1、bx1、bx2、bx3、x2；共用单浏览器、逐节落状态。
python3 scripts/batch_run.py

# 只处理一节或一本书；不会强制重跑未变的通过项。
python3 scripts/batch_run.py --book x1
python3 scripts/batch_run.py --section x1-1-1

# 导入另一worker已完成的检查，不重复打印；会核当前指纹和产物哈希。
python3 scripts/batch_run.py --adopt-existing

# 仅刷新入口与状态说明，不生成或验证内容。
python3 scripts/batch_run.py --portal-only

# 独立原文保留审计；不是数学审定。
python3 scripts/batch_audit_sources.py
```

`--force` 仅用于故意重验某些节点，不作为默认恢复方式。不要两个worker写同一节点或共享资源；跨册工作也应先约定范围。脚本更新后需重启正在运行的worker，不能让旧进程用新文件哈希冒充新逻辑。

## 落盘位置

- `batch/manifests/catalog.json`：五册、原章号、各节和章末节点清单。
- `batch/sections/{册ID}/{节ID}.json`：完整来源、行号、题答、重点、显式问题。
- `batch/patches/`：来源错号/数学冲突的提议或已复核证据，不是修改过的原资料。
- `batch/reviews/`：独立复核JSON与简报，记录模型哈希，模型变更后旧复核不再自动当当前结论。
- `batch/state/`：进度、逐节状态、独立来源保留对账。
- `outputs/五册教材教参整合/`：网页版入口、双版、学生ZIP、逐节检查JSON和实际打印检查PDF。

## 通过与限制

来源缺失、答案未配对、公式错误、题块可同页却跨页、资源缺失或学生内容泄漏均不能当作完成。超过整页的长题允许续页并必须明示。真正源稿冲突保持待核，不按列表顺序猜答案，不用删题提高通过率。

当前内容以原教材、正式教参为基础；OCR修复、编辑强调和数学修订明确分开。批量结构化底稿不等于每节已完成深入教法润色，正式出版前仍需完整数学与编辑审定。
